What this does

A summary of each section is written as a block at the top of that section, so it is read aloud before the section itself, highlighted like any other paragraph, and searchable. Turn it off per article with Show summaries in the player, or skip it in the audio with Skip summaries.

Any endpoint that speaks the OpenAI protocol works, so the model is yours to choose. Summarising queues a rebuild, because a new block moves the paragraphs after it.

Model

Any endpoint that speaks the OpenAI protocol works, which today is nearly all of them. Picking a provider fills in its address and one model worth starting on; the model is a typed name, so anything the endpoint accepts works, and the address is editable for anything not listed.

One key per endpoint, kept in the database on this machine. The key you type is filed under the endpoint above, so a DeepSeek key and a Gemini key live side by side and picking a provider brings its own. Leave the box blank to keep the key that endpoint already has.

{% if cfg.key_source == 'environment' %} This endpoint has no key stored, so it is using TEXTCAST_SUMMARY_API_KEY from the environment. That one variable is used by any endpoint with nothing stored, whichever provider it is for. {% else %} TEXTCAST_SUMMARY_API_KEY supplies a key to any endpoint that has none stored. {text} is where the section goes. It is written for the ear: no markdown, no bullets, nothing a voice would read out as punctuation.

Saving stores the settings and nothing else. No article is summarised until you ask for one.
